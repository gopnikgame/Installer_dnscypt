## 🚀 Быстрая установка

### Для Linux (systemd, SysVinit, OpenRC или runit):
```bash
sudo bash -c "$(wget -O - https://raw.githubusercontent.com/gopnikgame/Installer_dnscypt/main/quick_install.sh)"
```

Установщик отдельно определяет семейство дистрибутива и фактически работающую
init-систему. На OpenWrt используется специализированный procd-модуль.

> [!WARNING]
> Поддержка Devuan/SysVinit, OpenRC и runit реализована и проверена
> автоматическими тестами определения системы и синтаксиса скриптов, но полный
> цикл установки, переключения DNS, перезагрузки и отката ещё требует проверки
> на живых системах. До завершения таких испытаний используйте эту поддержку
> только там, где доступна консоль и можно вручную восстановить DNS.

### Для OpenWRT (специализированный установщик):
```bash
# Скачать специальный скрипт для OpenWRT
wget -O /tmp/install_openwrt.sh https://raw.githubusercontent.com/gopnikgame/Installer_dnscypt/main/modules/install_openwrt.sh

# Запустить установку
sh /tmp/install_openwrt.sh
```

**Или одной командой:**
```bash
sh -c "$(wget -O - https://raw.githubusercontent.com/gopnikgame/Installer_dnscypt/main/modules/install_openwrt.sh)"
```

> **✨ Специальный скрипт для OpenWRT:**
> - ✅ Полностью адаптирован для OpenWRT (ash/BusyBox)
> - ✅ Автоматическая настройка dnsmasq, firewall, NTP
> - ✅ Система автоматического отката при ошибках
> - ✅ Защита от DNS-утечек
> - ✅ Проверка версии и свободного места
> - ✅ Детальная диагностика и логирование

**После установки:**

На Linux:
```bash
sudo dnscrypt_manager
# или
sudo dnscrypt-manager
```

На OpenWRT:
```bash
# DNSCrypt уже настроен и работает!
# Проверка статуса:
/etc/init.d/dnscrypt-proxy status

# Просмотр логов:
logread | grep dnscrypt

# Тест DNS:
nslookup google.com 127.0.0.53
```

### 🔧 Особенности установки на OpenWRT

**Специализированный установщик включает:**
- ✅ Установка через `opkg` (dnscrypt-proxy2)
- ✅ Автоматическая настройка dnsmasq (форвардинг на 127.0.0.53)
- ✅ Конфигурация firewall (перенаправление DNS + блокировка DoT)
- ✅ Настройка NTP по IP (избегание DNS-петли)
- ✅ Отключение ISP DNS (защита от утечек)
- ✅ Система автоматического отката при ошибках
- ✅ Добавление в sysupgrade.conf (сохранение при обновлении)
- ✅ Оптимизированный кэш (4096 записей)
- ✅ Проверка версии OpenWRT и свободного места
- ✅ Использование BusyBox ash shell (POSIX-совместимый)

**Что делает скрипт:**

1. **Предварительные проверки:**
   - Права root
   - Версия OpenWRT (19.07+)
   - Свободное место (минимум 10MB)
   - Подключение к интернету

2. **Установка и настройка:**
   - Установка dnscrypt-proxy2 через opkg
   - Создание оптимизированной конфигурации
   - Настройка dnsmasq для форвардинга
   - Отключение кэша dnsmasq (использует кэш DNSCrypt)
   - Настройка NTP серверов по IP

3. **Безопасность:**
   - Отключение ISP DNS (peerdns=0)
   - Перенаправление всех DNS запросов на DNSCrypt
   - Блокировка DNS-over-TLS (порт 853)
   - Включение DNSSEC

4. **Автоматический откат:**
   - Создание резервных копий всех изменений
   - Автоматический откат при любой ошибке
   - Восстановление всех служб
   - Удаление пакета если установка не удалась

### 🧪 Статус поддержки систем инициализации

- `systemd` — основной Linux-сценарий проекта.
- `SysVinit`, `OpenRC`, `runit` — реализованы нативные службы и общий слой
  управления, пройдены синтаксические и мок-тесты.
- Devuan и альтернативные init-системы — **требуют проверки на живых системах**:
  установка, запуск после перезагрузки, занятость порта 53, DNS-резолвинг,
  журналы, удаление и автоматический откат.
- `procd` — обслуживается отдельным установщиком OpenWrt.

До завершения живых испытаний не используйте экспериментальные сценарии на
удалённой машине без резервного канала доступа.

## 🆕 Новые функции анонимного DNS

### 🌍 **Автоматическая региональная настройка**

**Как это работает:**
1. **Определение геолокации** - система автоматически определяет ваше местоположение
2. **Поиск релеев** - умный алгоритм находит оптимальные релеи в вашем регионе и близлежащих странах
3. **Тестирование скорости** - каждый релей проверяется на скорость отклика
4. **Автоматическая конфигурация** - создается оптимальная конфигурация согласно документации DNSCrypt

**Пример работы:**🌍 Геолокация сервера:
  IP адрес: 46.173.17.70
  Страна: Russia (RU)
  Регион: St.-Petersburg
  Город: St Petersburg

📡 Найдено релеев для анонимизации: 10
  ⚡ anon-cs-dus (47ms)
  ⚡ anon-cs-de (50ms)
  ⚡ anon-cs-berlin (51ms)

✅ Применена конфигурация:
  Серверы: Wildcard (*) - автоматический выбор
  Релеи: топ-3 самых быстрых из региона
### 📊 **Интерактивный просмотр серверов и релеев**

- **Просмотр по регионам** - структурированный список серверов и релеев по странам и городам
- **Поиск по критериям** - найти серверы по названию страны, города или имени сервера
- **Статистика** - общая информация о количестве доступных серверов и релеев
- **Обновление списков** - загрузка свежих данных из интернета

## 🐛 Решение проблем

<details>
<summary><b>🔄 Проблемы при установке</b></summary>

### При первой установке может потребоваться перезагрузкаsudo reboot**Причина:** Изменения в сетевых настройках требуют перезагрузки для полного применения.

### Ошибки загрузки модулей# Принудительное обновление всех модулей
sudo dnscrypt_manager
# Выберите пункт "Обновить все модули"
### Проблемы с геолокацией
- **Проблема:** Не удается определить местоположения
- **Решение:** Проверьте подключение к интернету, используйте VPN если необходимо
- **Альтернатива:** Выберите релеи вручную в пункте "Настроить маршруты для анонимизации"

</details>

<details>
<summary><b>⚙️ Конфликты служб</b></summary>

### Конфликты с systemd-resolved
Скрипт автоматически обнаруживает и решает конфликты, но при необходимости:sudo systemctl disable systemd-resolved
sudo systemctl stop systemd-resolved
### Порт 53 занят другим процессом# Автоматическое исправление
sudo dnscrypt_manager
# Выберите пункт 5: "Исправить DNS резолвинг"

# Или ручная диагностика
sudo lsof -i :53
sudo netstat -tulpn | grep :53
</details>

<details>
<summary><b>🎭 Проблемы с анонимным DNS</b></summary>

### Сообщения "incompatible with anonymization"
- **Причина:** Роутер не поддерживает фрагментированные UDP пакеты
- **Решение:** Включите опцию `skip_incompatible = true` в настройках
- **Автоматически:** Новая версия автоматически включает эту опцию

### Маршруты не работают# Используйте встроенное исправление
sudo dnscrypt_manager
# Пункт 6 → Пункт 6: "Исправить конфигурацию анонимного DNS"
### Ошибки с релеями
- **Важно:** Серверы и релеи должны управляться разными организациями
- **Проверка:** Используйте пункт "Просмотр серверов и релеев" для анализа
- **Автоматически:** Новый алгоритм автоматически выбирает релеи из разных стран

### Низкая скорость анонимного DNS# Автоматическая оптимизация
sudo dnscrypt_manager
# Пункт 6 → Пункт 8: "Автоматическая настройка по региону"
### Отладка проблем
Включите подробное логирование:# В дополнительных настройках установите log_level = 3-5
# Затем проверьте логи
journalctl -u dnscrypt-proxy -f
</details>

<details>
<summary><b>⚡ Проблемы производительности</b></summary>

### Медленная работа анонимного DNS
1. **Автоматическая оптимизация:**# Пункт 6 → Пункт 8: "Автоматическая настройка по региону"
2. **Ручная оптимизация:**
   - Используйте пункт "Тестировать время отклика серверов"
   - Выбирайте географически близкие релеи
   - Избегайте длинных маршрутов через множество стран

3. **Стратегии оптимизации:**
   - **Для скорости:** Используйте релеи из соседних стран
   - **Для приватности:** Используйте релеи из разных континентов
   - **Балансированный подход:** Автоматическая настройка по региону

### Высокое время отклика DNS# Смените на более быстрые серверы
sudo dnscrypt_manager
# Пункт 4: "Изменить DNS сервер"
</details>
